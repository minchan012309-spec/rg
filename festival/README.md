# 학교 축제 2인 리듬게임

게임 제목은 현재 **RHYTHM DUEL**로 표시합니다. `web/game/title.mjs`에서 바꾼 뒤 다시 빌드하세요.

## 실행

- 태블릿에서는 `RhythmDuel-Pad.html`을 브라우저에서 가로로 열고, 메뉴와 화면 아래 색 버튼을 터치하세요. 플레이어가 교대하면 같은 터치 버튼판을 다음 플레이어가 사용합니다.

- Mac에서는 `dist/RhythmDuel.html`을 Chrome이나 Edge로 엽니다. Supabase 연결 없이도 연주하고 이 브라우저의 팀 점수판을 볼 수 있습니다. 메뉴 BGM은 첫 키 입력이나 클릭 후 시작합니다.
- Windows x64에서는 `dist/RhythmDuel.exe`를 엽니다. Windows에 설치된 Edge 또는 Chrome의 앱 창을 띄웁니다. 게임과 음원은 EXE에 들어 있습니다.
- ESP32 두 대를 게임 PC에 연결하고 **버튼 설정**을 엽니다. 플레이어별로 큰 빨강·흰색과 작은 빨강·초록·파랑을 선택한 뒤 실제 버튼을 눌러 등록하고 저장합니다. 이미 등록된 키를 누르면 두 배정이 서로 바뀝니다. 설정은 게임 PC에 저장됩니다. 입력이 늦게 잡히면 같은 화면에서 입력 보정값을 올리고, 빠르게 잡히면 내립니다. 본게임의 짧은 박자 안내음과 타이밍 바 속도(6·8·10박)도 같은 화면에서 조정합니다.
- **버튼 설정 → 경기 버튼 모드**에서 5버튼 또는 빅돔 2버튼을 선택합니다. 빅돔 모드는 경기 입력과 타이밍 바에 큰 빨강·흰색만 쓰고, 작은 버튼은 메뉴 조작에 사용할 수 있습니다.
- 메뉴에서 P1의 큰 버튼 둘로 이동하고, 작은 빨강으로 선택, 작은 초록으로 뒤로, 작은 파랑으로 팀 점수판을 엽니다. 게임 중 Esc로 일시정지하거나 재개합니다. 일시정지 메뉴의 경기 포기를 선택하고 확인하면 해당 기록을 저장하지 않고 메인화면으로 돌아갑니다.
- 곡을 고른 뒤 소프트, 미디엄, 하드, 지옥을 선택합니다. 소프트는 한 박씩 쉬면서 두 번, 미디엄은 두세 번, 하드는 세네 번, 지옥은 매 정박에 누릅니다. Remix 4의 하드는 첫 턴부터 네 번을 누르고 판정 폭이 더 좁습니다. 게임 화면은 16:9 비율로 맞추며 상단 ⛶ 버튼으로 전체 화면을 켭니다.
- 미니게임 20종이 곡 안에서 이어집니다. 각 장면에서 P1과 P2가 한 턴씩 플레이한 뒤 다음 장면으로 넘어갑니다. 플레이 중인 캐릭터 하나가 전용 무대에 등장합니다. 위쪽 타이밍 바의 버튼 아이콘이 판정 원과 겹칠 때 같은 색과 크기의 버튼을 누릅니다. 무대 오브젝트도 해당 버튼의 색으로 표시됩니다. 허들은 옆에서 오고, 요리 재료는 철판에 떨어지며, 북은 제자리에서 좁아지는 원으로 타이밍을 알려줍니다.
- 같은 미니게임에서는 1P 전에만 동일한 리듬을 두 번 시범으로 보여줍니다. 두 플레이어는 같은 패턴을 치며 2P는 준비 화면으로 바로 넘어갑니다. 각자 실전 전에는 세 박 동안 화면 가운데에 3·2·1과 짧은 효과음이 나오며, 첫 버튼과 접근하는 물건이 표시됩니다. 내 차례에는 타이밍 바의 판정 원과 아이콘이 겹칠 때 표시된 버튼을 누르세요. P1과 P2가 번갈아 진행합니다. 키를 누르면 판정과 관계없이 동작과 효과음이 나옵니다. PERFECT는 만점, GOOD은 그 판정의 65%를 얻습니다. 플레이어별 최종 점수는 곡에 관계없이 16,000점 만점이며, 팀 순위는 두 점수의 합계로 정합니다.
- 세 MP3를 처음부터 끝까지 재생합니다. 전체 음원에서 주박을 추적한 채보를 사용하고, 음악과 시범 효과음은 같은 Web Audio 클록에서 재생합니다.

- 버튼 설정 또는 경기 중 Esc 메뉴에서 전시용 자동 플레이를 켜거나 끌 수 있습니다. 자동 입력이 사용된 경기는 결과를 보여주고 순위에서는 제외합니다.

## 축제 운영 연결

1. [Supabase 대시보드](https://supabase.com/dashboard)에서 프로젝트를 만들고 SQL Editor에서 `supabase/festival.sql`을 실행합니다.
2. Authentication → Users에서 운영자 이메일 계정과 게임 PC 이메일 계정을 각각 만들고 확인 상태를 켭니다. 두 계정의 이메일을 아래에 대입해 SQL Editor에서 실행합니다.

   ```sql
   insert into public.festival_users(user_id, role)
   select id, case when email = 'operator@example.com' then 'admin' else 'station' end
   from auth.users
   where email in ('operator@example.com', 'game-pc@example.com')
   on conflict (user_id) do update set role = excluded.role;
   ```

3. 휴대폰에서 [GitHub Pages 관리자 화면](https://minchan012309-spec.github.io/rg/operator-web/)을 엽니다. 다른 저장소에 배포하려면 Pages의 배포 대상을 `main` 루트로 설정합니다.
4. 게임의 **운영 연결**에는 프로젝트 URL, Publishable 키, 게임 PC 계정으로 로그인합니다. 휴대폰 관리자 페이지에서는 같은 URL과 Publishable 키, 운영자 계정으로 로그인합니다.
5. 휴대폰에서 팀명과 두 사람의 학번·이름을 저장합니다. 곡을 보내면 게임 PC가 난이도 선택 화면을 엽니다. 현장에서 캐릭터를 직접 선택하거나, 관리자가 게임 시작을 누르면 현재 캐릭터로 바로 시작합니다. 재생 제한이 있는 브라우저에서는 게임 PC의 선택 버튼으로 시작하세요.
6. 결과가 저장되면 휴대폰에서 해당 경기의 두 점수를 수정할 수 있습니다. 게임 PC에서 점수판을 다시 열면 변경된 순위를 읽습니다.

프로젝트 URL과 Publishable 키는 두 화면에 입력합니다. 비밀번호는 각 로그인 화면에 입력합니다. 학번은 관리자 권한으로 읽는 운영 데이터에 보관되고, 팀 점수판에는 팀명과 점수가 표시됩니다. 연결 전에 진행한 로컬 경기는 해당 PC의 로컬 점수판에 저장됩니다. 서버 운영은 게임 PC 한 대를 기준으로 합니다.

## 다시 빌드

이 저장소에는 실행 파일이나 MP3를 커밋하지 않습니다. 받은 MP3 3개를 순서대로 `festival/web/game/audio/bgm1.mp3`, `bgm2.mp3`, `bgm3.mp3`로 복사하세요. 동봉된 채보를 그대로 사용할 수 있습니다.

- 브라우저용 HTML: `python3 festival/build-web.py`
- Windows x64 EXE: `./festival/build-windows.sh` (Go 1.24 이상)
- 채보 재생성: `python3 festival/make_charts.py "game bgm1.mp3" "game bgm2.mp3" "game bgm3.mp3"` (FFmpeg, NumPy, SciPy)
- 판정 검사: `node --test festival/tests/*.test.mjs`

Mona12와 Bithumb Gothic Original은 요청한 CDN 주소를 사용합니다. 주소에 접속할 수 없을 때는 운영체제 글꼴로 표시합니다.
